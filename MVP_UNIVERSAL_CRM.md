# MVP универсальной CRM-системы

## 1) Идея продукта

Создаем CRM-платформу с **общим ядром** (клиенты, сделки/заказы, расписание, сотрудники, уведомления, аналитика),
которую можно быстро адаптировать под разные ниши через:

- шаблоны бизнес-процессов,
- настраиваемые поля,
- отраслевые модули,
- роли и права,
- отчеты по шаблонам.

Цель MVP: за 6–8 недель получить рабочий продукт для 2–3 ниш (например: салон красоты, автосервис, ремонт смартфонов),
с возможностью быстрого подключения новых вертикалей.

---

## 2) Принципы архитектуры MVP

### Core (обязательно для всех)

1. **CRM-база**
   - Клиенты (контакты, история взаимодействий)
   - Заказы/заявки/визиты (единая сущность `WorkItem`)
   - Статусы воронки
   - Комментарии и файлы

2. **Календарь и задачи**
   - Запись клиентов в расписание
   - Назначение ответственного сотрудника
   - Напоминания клиенту и сотруднику

3. **Каталог услуг/товаров**
   - Позиции, цены, длительность, себестоимость
   - Склад в простом виде (остатки, списание)

4. **Финансы light**
   - Чек/оплата (нал/безнал)
   - Доход по дням
   - Базовые отчеты (выручка, средний чек)

5. **Коммуникации**
   - Telegram/WhatsApp/SMS как минимум через один канал в MVP
   - Шаблоны сообщений (подтверждение записи, напоминание)

### Extensibility (для отраслевой адаптации)

- **Custom fields** для клиентов и заказов
- **Pipeline templates** (этапы под конкретный бизнес)
- **Role templates** (админ, мастер, менеджер)
- **Industry packs** — наборы преднастроек:
  - Beauty Pack
  - AutoService Pack
  - Repair Pack
  - Retail/Flower Pack

---

## 3) Отраслевая адаптация (пример)

### Салон красоты
- Сущность: запись на услугу
- Специфика: длительность услуги, мастер, повторные визиты
- KPI: загрузка мастеров, retention, no-show rate

### Цветочный магазин
- Сущность: заказ букета + доставка
- Специфика: дата/время доставки, адрес, срочность
- KPI: средний чек, повторные покупки, время сборки/доставки

### Автосервис
- Сущность: заказ-наряд
- Специфика: авто (VIN/госномер), этап диагностики, запчасти
- KPI: цикл ремонта, маржинальность работ, возвраты

### Ремонт смартфонов
- Сущность: ремонтный тикет
- Специфика: модель устройства, дефект, статусы ремонта
- KPI: срок ремонта, % успешного ремонта с первого раза

### Кофейня (как CRM + лояльность)
- Сущность: клиент + покупки/карта лояльности
- Специфика: акции, повторные визиты, сегменты
- KPI: LTV, частота посещений, конверсия акций

---

## 4) Что должно быть в MVP (must-have)

1. Авторизация + роли
2. Клиенты + история
3. Заказы/записи + статусы
4. Календарь
5. Уведомления (минимум 1 канал)
6. Простая касса/оплаты
7. Отчеты: выручка, конверсия по этапам, загруженность сотрудников
8. Конструктор полей (без кода)

### Что можно отложить (post-MVP)
- Полноценный склад с партиями
- Сложные интеграции с IP-телефонией
- AI-прогнозирование
- Маркетинговая автоматизация уровня enterprise

---

## 5) Технический каркас (прагматично)

- Backend: Node.js (NestJS) или Python (FastAPI)
- DB: PostgreSQL
- Frontend: React + компонентная админка
- Notifications: очередь задач + провайдер сообщений
- Deployment: Docker + cloud VM

> Для быстрого старта важнее **чистая доменная модель** и модульность, чем «идеальная» инфраструктура.

---

## 6) Доменная модель (упрощённо)

- `Tenant` (компания/филиал)
- `User` (сотрудник)
- `Customer`
- `WorkItem` (универсальная заявка/заказ/визит)
- `WorkItemType` (салон/ремонт/доставка...)
- `PipelineStage`
- `ServiceItem` / `ProductItem`
- `ScheduleSlot`
- `Payment`
- `MessageLog`
- `CustomFieldDefinition` + `CustomFieldValue`

Эта модель позволяет хранить общую логику, а различия ниш вносить настройками.

---

## 7) План запуска MVP (8 недель)

### Неделя 1–2
- Валидация 2–3 ниш (20+ интервью суммарно)
- Карта core-фич
- Проектирование доменной модели и UX-потоков

### Неделя 3–4
- Реализация auth, клиенты, work items, статусы
- Базовый UI кабинета

### Неделя 5–6
- Календарь, уведомления, оплаты, отчеты
- Custom fields

### Неделя 7
- Отраслевые шаблоны (минимум 2 pack)
- Пилот с первыми клиентами

### Неделя 8
- Доработка по обратной связи
- Подготовка onboarding и тарифов

---

## 8) Метрики успеха MVP

- Activation: >60% компаний создали первый заказ в первые 24 часа
- Time-to-value: <30 минут до первой «полезной операции»
- WAU/MAU: >0.5
- Retention D30: >35% для SMB
- NPS пилота: >30

---

## 9) Риски и как снизить

1. **Слишком широкая функциональность**
   - Решение: жесткий core + 2–3 вертикали на старте

2. **Сложность интерфейса**
   - Решение: сценарный onboarding и отраслевые пресеты

3. **Долгая адаптация под нишу**
   - Решение: templates + custom fields + готовые pipeline

4. **Слабая ценность без интеграций**
   - Решение: сначала довести ценность offline-процесса, потом расширять интеграции

---

## 10) Коммерческая модель для старта

- Подписка по количеству сотрудников/точек
- Тарифы: Start / Growth / Pro
- Дополнительная монетизация:
  - платные интеграции,
  - отраслевые пакеты,
  - white-label для партнеров-интеграторов.

---

## 11) Следующий шаг

Сразу после MVP стоит сделать:
1) 3 вертикальных шаблона,
2) мастер первичной настройки,
3) импорт клиентов из Excel,
4) мобильный интерфейс для мастеров/сотрудников.

Это даст резкий рост активации и повторного использования.
